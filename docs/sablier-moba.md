# MOBA local — experimental mode and remaining work

`src/games/rpgMoba.js` is an isolated, serializable lane bookkeeping module. `src/games/rpgMobaLocal.js` is an experimental bridge for local two-seat duels: it creates a real mana-essai duel and routes basic hand summons through the existing engine, mapping the five engine slots to 2/1/2 lane slots. It uses the engine's `pvp` flag only to select manual control for both seats; it does not use the network or referee. The bridge requires completed mulligans, a started mana system, the active player's main phase, an active lane and a free slot. It validates the lane/engine board agreement and fails closed when they diverge. The engine handles mana, hand removal and ordinary summoning restrictions; MOBA forbids the mana-essai full-board sacrifice by requiring an empty slot first.

An **experimental local two-player game** is available in the menu where online play is disabled. It is not the requested complete MOBA mode: both players use a fixed 30-card deck, containing eight audited creatures and seven audited global spells (two copies of each), validated against the existing mana-essai deck rules. Both seats choose their mulligan privately before the first turn. At the end of a turn, the active player chooses any cards above the six-card hand limit instead of leaving the choice to the engine. Fast-response windows are not exposed. It has no AI or online referee integration. The menu preserves the existing online link if online mode is enabled.

The bridge supports draw-on-arrival using the original effect, but temporarily refuses other arrivals, boarding, interception or player-HP costs. Its experimental combat path accepts only the audited creatures, including Furie, Overkill and Provocation: it checks lane isolation, delegates combat to the engine, routes each direct hit to its lane, removes conquered-lane occupants and stops on the second conquest. These restrictions are scaffolding, not a proposed final card pool. The seven global spells are executed by the real engine and removed creatures are reconciled with lane slots. Card-effect targeting, most creature entry/exit paths, resurrection and player-HP effects are not yet connected. Deck-exhaustion fatigue still affects the legacy sorcerer HP and requires a MOBA-specific resolution; extended games can therefore stall. The UI does not support saves or resuming a game after exiting. Placement rollback on unexpected changes restores serialized duel state only; engine-side ephemeral journals and RNG are not transactional.

`tests/rpg-moba.test.js` covers isolated lane rules; `tests/rpg-moba-local.test.js` covers summons, turns, limited combat, global spells and a complete engine-level path to victory. `tests/rpg-moba-board.test.js` covers rendering, private handoffs and an interactive path through summons, turns, combat, discard and victory in jsdom using a controlled combat fixture. These tests do not validate the full card catalogue or a complete real-browser match.

## Architecture inspected

* `rpgDuel.js` owns the existing mutable duel state, mana, placement, creature abilities, attack declaration and resolution, death, scheduled returns, turn transitions and winner (`rpgVainqueur`). It uses `joueur`/`sorcier` for the two sides. Mana Essai already has five fixed slots but permits sacrifice on a full field, which MOBA must not inherit accidentally.
* `rpgCards.js` defines cards, effects, targets and keywords; card execution is distributed through `rpgDuel.js`. Examples include arrival damage and healing, combat effects, temporary bonuses, global damage, token creation, resurrection and Tenacité. `rpgAI.js` makes choices against the existing, unpartitioned battlefield.
* `RpgDuelPage.jsx` owns the main menu, board, targeting, phases, local opponent and victory display. `RpgPvpBoard.jsx` uses that same page. The menu opens the local trial in the disabled online entry, leaving the enabled online link unchanged.
* `rpgPvp.js` validates and applies online intentions, including attack declaration and defensive responses; `src/server/sablierArbitre.js` and `api/sablier-duel.js` are the authoritative online path. Server state and filtered views must both understand lanes before online MOBA can be offered.

## Work required before release

1. Integrate lane assignment at **all** creature entry points: hand summons, tokens, temporary exile, Tenacité and other scheduled returns. Preserve the original lane across return (current scheduled-return records contain a card ID, not a lane); decide how effects creating multiple creatures select their legal slots. Clear or invalidate pending returns on conquest without breaking other copies of the same card.
2. Extend the combat bridge to more ability-bearing cards and the declaration/defense interaction. Blocker selection, forced blocking, targeted attacks and AI must all be constrained by lane. `rpgDuel.js` now offers an optional direct-hit callback and checks lane identity in its blocking predicate when MOBA entities carry one; classic entities have none. The local bridge currently supports a small audited set including Provocation, Furie and Overkill. It uses a new engine helper that removes conquered creatures through the existing exile cleanup (without death triggers or scheduling a return) and clears their temporary bonuses. Audit the destination and cleanup for weapons, prisoners, pending effects, deaths and already-scheduled returns, and support more modifiers, critical hits, shields and explicit piercing effects before release.
3. Audit the full card catalogue and every engine effect, including auras, targeted and global abilities, damage, healing, creation, destruction, bounce, exile and returns. Existing card text often targets a *sorcier*, not a lane: a consistent, explicit mapping/selection rule is needed before those effects can be supported without inventing card effects. The bookkeeping module intentionally makes no such choice.
4. Extend the trial board to all cards and targets, add response windows, and test full matches in a real browser on desktop and mobile. The trial now provides private mulligans, player-selected discard, responsive styling, keyboard-operable buttons and basic health/conquest animation; these do not substitute for browser accessibility and device testing. Add an AI if desired. Online PvP is out of scope for this phase; if added later, the referee must validate every action, persist the lane state, filter views correctly and have concurrency/reconnect tests.
5. Run end-to-end tests with real cards and both players, including blocked/unblocked combat, lane isolation, full lanes, conquest cleanup, resurrection, global effects, victory, post-victory rejection and a classic-mode regression. Test the online path server-side only if enabled later.

## Module contract

The lane module tracks HP, slot occupancy, permanent entity-to-lane assignments, conquest and winner. `mobaValiderBlocages` validates **only lane isolation**, not legal combat. `mobaInfliger` accepts damage already resolved by the real engine and reports removed entity IDs; callers must perform actual engine cleanup atomically. `mobaSoigner` clamps at 10 and refuses inactive lanes. The local combat bridge currently does this cleanup via `rpgRetirerEntitesConquete` for its restricted test cases. Neither module alone is a complete authoritative game.

## Modified files

* `src/games/rpgMoba.js`: lane bookkeeping and validation.
* `src/games/rpgMobaLocal.js`: experimental local duel, fixed starter pool, private mulligan and end-of-turn discard, summoning, global-spell and limited combat bridge.
* `src/games/rpgDuel.js`: optional per-hit routing hook, lane-aware blocking for marked entities, and engine cleanup helper; classic entities and calls retain their original path.
* `src/games/RpgDuelPage.jsx`: opens the local MOBA trial in place of the disabled online entry; keeps the enabled online link intact.
* `src/games/RpgMobaBoard.jsx` and `src/games/rpg-moba.css`: local hot-seat test board and responsive styling, using the existing table and card artwork.
* `tests/rpg-moba.test.js`, `tests/rpg-moba-local.test.js`, `tests/rpg-moba-board.test.js` and `tests/rpg-mode-cards.test.js`: isolated, engine, board and menu tests.
* `docs/sablier-moba.md`: design decisions, limitations and remaining work.

## Validation of the latest local-board changes

* The focused MOBA/classic/PvP/health/combat run passed 311 tests. The PvP suite passed 53 tests and the production build succeeded (with existing chunk-size/dynamic-import warnings).
* The larger `npm run check:rpg` suite passed 1,536 of 1,548 tests. Its 12 failures were reproduced with the modified MOBA files restored temporarily to the current `HEAD`: catalogue preview, collection/booster and Link expectations, route wrapping, six legacy 4K image-size assertions, and the Souk offer count. They are not fixed by the MOBA changes.
* The interactive match test uses jsdom and a controlled deck/mana fixture, not a real-browser match. A local Chromium launch was attempted, but required system NSS/NSPR libraries were unavailable. Desktop/mobile rendering and accessibility still need real-device/browser review.
